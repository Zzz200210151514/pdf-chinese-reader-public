# V4.1 通用优化说明

V4.1 在 V4 五层流程（解析 → 分类 → 翻译调度 → 术语控制 → 布局重建）上的定向优化，目标是减少返工：让问题在翻译前暴露、让审核结论有工具承载。

## 流程门禁前移

- `prepare` 在本地完成解析、分类和结构预检（`structure.py` 只核对几何、覆盖、保护区、读序，不用假译文、不做字体拟合），审核通过前 `jobs` 恒为空。
- `plan --reviewed` 通过门禁后冻结来源指纹（`frozen-map.json`），之后的 `translate`/`finish` 以指纹为准，来源被改会明确报 `stale-translation-plan` 而不是带病继续。
- 来源 PDF 在 prepare 时快照到 `work/source.pdf`，Zotero 等工具在阶段之间移走原文件也不影响续做。

## 返工修复（本次审阅整改）

- `prepare` 不再无条件覆盖已审核目录：存在 `review_resolutions` 或冻结计划时拒绝覆盖，需 `--force`。
- 新增 `resolve` 命令：一条命令写入审核结论并自动重新 plan，告别手拼 `id|check|page` 键。
- 新增 `status` 命令：读运行产物，输出当前阶段和唯一的下一步命令。
- 新增 `doctor` 命令：翻译前探测依赖和系统字体，输出可粘贴的 `fonts:` 配置，并预检希腊字母/上下标覆盖。
- `finish --source` 改为可选，默认使用 prepare 的快照。
- 缺字检查从 finish 的硬失败前移到 `translate --translations`：按 ID 报告，只重写缺的条目。
- `resolve_fonts`：备用字体缺失降级为警告而非硬失败；支持绝对路径和跨目录字体；字段类型错误给出可读报错。
- 术语库从约 15 条扩充到 78 条（chemistry / electrochemistry / environmental / membrane），`config.yaml` 明确 `domain` 语义，`validation_retries` 默认提高到 1。

## 缓存与恢复

- 逐 ID 缓存，键含原文、邻近上下文、术语版本、路由与可信指令；命中后仍校验，显式修订永远优先于缓存。
- 局部失败只重试/交接对应 ID；几何变化使旧缓存失效，字体和包大小变化不失效。
- `events.jsonl` 记录每阶段 UTC、状态和实耗；`translation-events.jsonl` 记录翻译调用与 usage。

## 质量边界（未改变）

- 结构、字体、像素、覆盖、链接门禁与 V4 相同；性能优化没有放宽任何保护标准。
- 自动检查通过不等于译文准确；视觉检查和阅读器点击仍需人工完成。
