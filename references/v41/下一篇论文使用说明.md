# 下一篇论文使用说明（V4.1）

面向陌生论文的操作顺序，默认单任务串行、重点校读。每一步只读取摘要、当前待译包和异常片段；完整坐标与验证 JSON 留本地。普通翻译不读取维护历史或重构脚本；轻微排版警告直接交付，只有实际影响内容或阅读的问题才局部修正，见 [返工边界](../../SKILL.md#检查与返工边界)。

## 0. 预检（环境变化或特殊符号时）

```powershell
python -X utf8 scripts/translator_v4.py doctor --source paper.pdf
```

doctor 检查 Python 依赖、探测系统字体，输出可直接粘贴进 `config.yaml` 的 `fonts:` 配置；带 `--source` 时还会预检论文中的希腊字母和上下标是否被字体覆盖，缺符号字体在翻译前就能发现。

## 1. prepare

新论文执行；已有工作目录先用 `status` 确认下一步，复用快照、审核与缓存。

```powershell
python -X utf8 scripts/translator_v4.py prepare --source paper.pdf --work work/paper --extractor local
```

本地解析、分类，生成 `source_map.json`、`review.json`、`structure-preflight.json`，此时 `jobs.json` 为空，不会派发翻译。**注意：如果目录里已有审核记录或冻结计划，prepare 会拒绝覆盖——这是保护，不是故障。** 确实要重来时显式加 `--force`。

## 2. 审核与 resolve

```powershell
python -X utf8 scripts/translator_v4.py status --work work/paper
```

status 读取运行产物，报告当前阶段和唯一的下一步命令。对照原页处理 `review.json` 里的待审项，逐条记录处理结论：

```powershell
python -X utf8 scripts/translator_v4.py resolve --work work/paper --issue-key "<id|check|page>" --note "<实际核对结论>"
```

resolve 把结论写进 `source_map.json` 的 `review_resolutions` 并自动重新 plan，不需要手改 JSON，也不会再触发「stale-translation-plan」。阻断级几何/覆盖问题不能豁免。没有待审项或最后一次 resolve 已完成冻结时，用 status 确认；尚未冻结才执行：

```powershell
python -X utf8 scripts/translator_v4.py plan --work work/paper --reviewed
```

## 3. translate（宿主翻译）

```powershell
python -X utf8 scripts/translator_v4.py translate --work work/paper
```

host 模式生成 `pending-jobs.json`。只取当前批次的 `blocks`、`neighbor_context`、`terms` 与必要 `instructions` 给模型；私有校验字段保留在文件中，不整份打印。宿主串行翻译缺失 ID，每批提交后读取剩余待办，避免重复处理已完成 ID：

```powershell
python -X utf8 scripts/translator_v4.py translate --work work/paper --translations batch.json --font-dir C:/Windows/Fonts
```

带 `--font-dir` 时，提交批次会做按 ID 的缺字预检，结果写入 `glyph-preflight.json`；先配置覆盖缺字的备用字体；确需改译时只修改这些 ID，不改科学含义。

## 4. finish

```powershell
python -X utf8 scripts/translator_v4.py finish --work work/paper --output outputs/paper.zh.pdf --font-dir C:/Windows/Fonts --reviewed
```

`--source` 可省略，默认使用 prepare 保存的 `work/paper/source.pdf` 快照。finish 执行字体拟合、原位重建和全量功能验证；缺字、溢出、保护区冲突未解决会停止并报告。

`finish` 内自动尝试有界行距调整和微型块拟合。`passed` 或 `passed_with_warnings` 均正常交付；警告不要求返修。目标是一次出稿，真实阻断才按 ID 集中处理后继续，不规定第二次必须成功。完整 rebuild 或生成 PDF 的干跑同样计入构建成本。`delivery.json` 记录实际成品路径与哈希，`status` 不再把合并中间产物当作交付。

## 已知失败模式与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `prepare` 报「already holds review decisions」 | 目录已有审核记录/冻结计划 | 用 `resolve` 继续，或确认后 `--force` 重来 |
| 批量 `resolve` 时前几条返回非零退出 | 每条 `resolve` 立即重新 plan，其余待审项未清时 plan 报错，但决策已写入 `source_map.json` | 忽略中间报错，继续逐条 resolve；最后一条成功后 `review_required_count` 归零 |
| `translate` 报 `missing-or-stale-translation-plan` | 来源图被改但指纹未冻结 | 重新审核后 `resolve` 或 `plan --reviewed` |
| `translate` 报占位符缺失/未知 | 引擎的 freeze/audit 规则更新后，旧 `pending-jobs.json` 的 token 编号失效 | 重新运行 `translate --work` 生成新的待译包，按新模板重新提交译文 |
| `glyph-preflight.json` 有缺字 ID | 正文字体缺字形 | 先给 `fonts.fallback` 配符号字体；确需改译时只改这些 ID |
| `finish` 报 `Protected area changed` | 保护文字提取内容变化，或保护图形像素差异超过 1% | 对照原页检查该对象是否被擦除/覆盖；≤1% 的抗锯齿差异只记警告，不会阻断 |
| finish 报缺字体 | 默认字体是 Windows 字体 | 先跑 `doctor` 拿本机 `fonts:` 配置 |
| 术语没注入 | `config.yaml` 的 `domain` 与论文领域不符 | 改成论文领域（如 membrane）再 plan |
| 门禁报 `unclassified-source-record` 等 | 陌生版式超出启发式 | 对照原页修正来源图后 `resolve` |

陌生论文的严格零开发介入验收尚未达标：选定论文在开发阶段仍可能发现问题，不能把维护耗时计为正常运行。只有维护或查验已测范围时才读 [回归测试与质量验证](回归测试与质量验证.md)。
